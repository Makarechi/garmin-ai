# Native model fallback decisions

The fallback policy preserves candidate order, skips already invalid or cooled candidates, and stops for a revoked permission or exhausted deadline. It records provider-wide and model-specific pauses with the expected precedence. Invalid replies can be saved before a later job attempt. A successful response is returned after one attempt even when the bookkeeping callback cannot persist the update.

Twenty-four pinned Python sequences matched the native attempt order, gate writes, checkpoints and final results. They covered quota, credential errors, invalid and truncated output, cooldowns, consent revocation, saved resume and arbitration between equal deadlines. Linux ARM64 ran offline at a peak of 7,311,360 bytes under 32 MiB and with no swap. The caller still supplies permission checks and integrates the durable gate, checkpoint and transport.
