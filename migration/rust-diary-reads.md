# Native owner diary reads

The diary read uses recorded time bounds and orders entries that start
inside the window before older overlapping episodes. It checks each
entry's immutable definition permissions before truncating the page.
Retired definitions remain queryable when their version allows it.
Entries with no recorded end keep the existing open-interval semantics.
The response preserves the canonical envelope and reports a caffeine
total only when the dose basis was specified.

Twenty-three ARM64 Linux requests matched pinned Python on disposable
TimescaleDB. They covered overlapping episodes, points on both time edges,
inferred and pending states, older and retired versions, hidden entries,
version-specific editing, and caffeine dose bases. Existing differential
fixtures for creation and idempotent retry, deletion and grouped undo,
and custom-entry corrections also passed after sharing timestamp decoding.

This read returns owner data. Model and channel use require their separate
consent filters and delivery checks.
