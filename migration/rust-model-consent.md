# Native model consent checks

The selection check binds the prepared client to the current integration, model and credential generation. The consent record must match the integration and cover the requested categories. Gemini fallback follows the configured order and includes only consented candidates. Text requests accept health and diary categories. Voice uses the separate audio category and requires a compatible provider.

The database checks saved onboarding choices immediately before a provider attempt. An install without onboarding keeps its legacy access rules. Once choices are saved, a request requiring an omitted category is denied. Damaged settings fail closed.

The paired fixture matched 24 provider decisions and eight saved onboarding decisions from pinned Python. It covered model and key changes, narrowed data categories, expired authorization, provider capability, fallback ordering, and malformed saved state. Linux ARM64 peaked at 7,585,792 bytes under 32 MiB with no swap. The fixture made no provider calls.
