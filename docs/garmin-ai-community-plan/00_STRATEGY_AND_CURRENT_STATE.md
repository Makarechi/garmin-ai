# Garmin AI: переход к продукту и проекту для сообщества

**Дата анализа:** 2026-10-04.
**Проверенный main:** `8d9bd0208da5891f836ce7045004ef729fa40aab`, merge PR #123 от 2026-10-01.
**Режим работы:** чтение репозитория и публичных первичных источников. Код, настройки репозитория и production не изменялись. Полный аудит безопасности и повторный прогон тестов не выполнялись.

## Решение

Следующая цель — не ещё один слой абстракций и не максимальное количество интеграций. Нужен **поддерживаемый self-hosted продукт с проверяемыми точками расширения**: новый человек получает пользу без помощи автора, а новый разработчик создаёт совместимое расширение без форка ядра.

Универсальность не означает одинаковые настройки для всех. Ядро и установка не зависят от автора; трекеры, источники, канал общения, AI и инициативы настраиваются под владельца.

Предлагаемое позиционирование: **личные данные с устройств и из дневника, контролируемые владельцем, с воспроизводимой аналитикой и необязательным AI-помощником**. Garmin остаётся первым глубоко поддерживаемым источником. Telegram остаётся поддерживаемым каналом. Мигрень/кофеин — выбираемые сценарии, а не определение всего продукта.

Не превращать проект в универсальную платформу для любой автоматизации, медицинскую систему диагностики или новый мессенджер. Не требовать немедленного переименования репозитория, CLI и схемы БД. Не смешивать эту работу с многопользовательским SaaS.

## Главная ценность, которую стоит показывать

Не «AI отвечает на вопросы» и не «скачиваем JSON из Garmin». Предлагаемая ценность — полный цикл:

1. Автоматически сохранить историю источников и её происхождение.
2. Добавить недостающий контекст обычной записью или сообщением.
3. Связать данные по корректному времени и смыслу, не превращая пропуски в нули.
4. Получить ответ с периодом, выборкой, ограничениями и источниками.
5. Исправить запись и увидеть пересчитанный результат.
6. Продолжать вести дневник при сбое Garmin, модели или канала.

Это продуктовая гипотеза. Проверять её нужно использованием чужими людьми, не количеством новых PR.

## Две аудитории, два пути

**Пользователь:** установить → попробовать → подключить свой источник → выбрать/создать трекер → получить первый полезный результат → использовать без сопровождения автора.

**Контрибьютор:** увидеть результат → воспроизвести на синтетике → выбрать маленькую задачу → изменить ограниченный участок/расширение → проверить локально → получить понятное ревью.

Первой аудиторией я бы выбрал технически самостоятельных владельцев Garmin и людей, которым нужен собственный дневник/аналитика. Это начальная аудитория, а не ограничение архитектуры навсегда. Немедленный массовый consumer launch создаст неподдерживаемые ожидания.

## Устройство продукта

Один репозиторий и модульное приложение остаются основной формой поставки. Логически выделяются:

- ядро данных, правил, диалога и проверяемой аналитики;
- официальные адаптеры источников, каналов и моделей;
- SDK и contract tests для расширений;
- декларативные пакеты трекеров/сценариев;
- приложение, onboarding, эксплуатация и документация.

На первом этапе официальный продукт и официальные адаптеры версионируются согласованно. Публичный контракт расширений получает свою явную версию. Независимый плагин не должен импортировать private ORM/session internals.

## Не делать сейчас

Не подключать WhatsApp и Viber только ради количества логотипов. Не обещать поддержку мессенджера на основании существования общего интерфейса. Не начинать marketplace с выполнением произвольного кода. Не переносить весь проект на другой язык. Не заменять PostgreSQL или вводить microservices без измеренного ограничения. Не запускать SaaS и не собирать личные данные пилота на сервер автора по умолчанию.

Не превращать лицензию, тексты и демонстрацию в повод отложить исправление correctness/privacy-блокеров. Подготовка публичного продукта и ограниченный технический переход могут идти параллельно.

## Условия успеха следующего этапа

Предлагаемые цели пилота, не текущие достижения:

- Из пяти новых установок минимум четыре проходят документированный путь без правок исходников и личного сопровождения автора.
- Первый demo-цикл занимает до 10 минут после запуска окружения; для реального подключения отдельно измеряются ожидание внешнего сервиса, MFA и загрузка истории.
- За семь дней оценивается использование и причины отказов; не требуется обещать статистические выводы из нескольких дней данных.
- Минимум два внешних разработчика выполняют ограниченный вклад; хотя бы одно расширение проходит contract tests без изменения runtime/domain.
- Отдельно зафиксированы результаты работы после restart, сетевых ошибок, отзыва согласия и восстановления backup.
- Публикуется честная матрица: implemented / synthetic-tested / live-verified / experimental / not implemented.

Звёзды и число PR можно наблюдать, но не использовать вместо этих критериев.
